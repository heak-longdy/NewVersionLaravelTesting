### In-Depth Feasibility & Architectural Analysis per Report

#### Report 1: Asset Ownership, Registration Card & Mignette Control Report
- **Can it be created?** **CONFIRMED (YES)**.
- **Business Purpose**: Master operational safe-custody control for physical vehicle registration cards, annual road tax mignette/vignette stickers, and technical inspection dates across the active portfolio.
- **Target Layout**: Sheet `Current Customer List` (26 operational columns, Row 2 header, Navy fill `#1F4E79`, white bold text).
- **Database Tables Verified**: `MKT_LOAN_CONTRACT`, `MKT_CUSTOMER`, `MKT_OFFICER`, `MKT_COLLATERAL_DE`, `MKT_LOAN_COLLATERAL`, `MKT_ASSET_DELIVERY`, `MKT_REPORT_ENGINE`, `MKT_FORM`.
- **Schema & Data Readiness**: 20 columns exist directly. 6 operational fields (`InspectionDate`, `InspectionStatus`, `RenewStartDate`, `RenewEndDate`, `CollateralKeepStatus`, `FilingCabinet`) have dedicated DDL provided in the plan, with fallback logic to existing fields (`ReceivedDate`, `IssuedDate`, `Maturity`, `ReceivedBy`, `HouseNo`) ensuring zero disruption if DDL execution is deferred.
- **Deliverables**: Refine [assetownership.py](file:///home/admin/Project/CBS/Tonle/local/Tonle/Report/assetownership.py), build OpenPyXL exporter, register `/Morakot/Report/AssetOwnership/Excel`, execute seed script.

#### Report 2: Asset Ownership - Tax Paper Control Report
- **Can it be created?** **CONFIRMED (YES)**.
- **Business Purpose**: Operational safe-custody and legal ownership audit report for agricultural machinery (John Deere Tractors) and heavy equipment (JCB Rollers) held under Customs/Import Tax Paper titles.
- **Target Layout**: Sheet `Tax Paper` (17 columns, Header Row 1, Light Gray fill `#D9D9D9`, Arial 10pt bold, date format `[$-409]d-mmm-yyyy;@`).
- **Database Tables Verified**: `MKT_LOAN_CONTRACT`, `MKT_CLOSED_LOAN`, `MKT_CUSTOMER`, `MKT_COLLATERAL_DE`, `MKT_OFFICER`, `MKT_LOAN_COLLATERAL`, `MKT_ASSET_DELIVERY`.
- **Schema & Data Readiness**: 100% computable from existing tables. Requires adding a SQL `UNION` with `MKT_CLOSED_LOAN` (so closed/paid-off contracts appear) and deriving `Collateral Keep` (`In TLF` vs `Not in TLF` based on `WithdrawalDate`) and `Status Trail` (`Actived Loan`, `Paid off`, `Write Off`).
- **Deliverables**: Update [taxpapercontrol.py](file:///home/admin/Project/CBS/Tonle/local/Tonle/Report/taxpapercontrol.py), build OpenPyXL exporter, register `/Morakot/Report/AssetOwnershipTaxPaper/Excel`, execute seed script.

#### Report 3: GPS - Master List Control All Loans Report
- **Can it be created?** **CONFIRMED (YES)**.
- **Business Purpose**: Master tracking list across all active, closed, and written-off contracts consolidating vehicle specifications, financial exposure (balance, overdue, DPD), loan lifecycle milestones, and primary GPS installation/supplier status.
- **Target Layout**: Sheet `Master list` (18 columns, Calibri 11pt Bold, Theme 8 Olive header, Theme 7 Teal header for Main GPS, Light Green `FF92D050` for Sub-GPS).
- **Database Tables Verified**: `MKT_LOAN_CONTRACT`, `MKT_CLOSED_LOAN`, `MKT_CUSTOMER`, `MKT_GPS_TRACKER`, `MKT_CATEGORY`, `MKT_PAST_DUE`, `MKT_PD_DATE`, `MKT_WRITE_OFF_DE`.
- **Schema & Data Readiness**: 12 fields direct, 4 calculated (`BalanceOverdue`, `OverdueDays`, `Asset Type`, `Loans Status`). Sub-GPS fields (Columns 15 & 16) default to `'No'` matching template sample records without needing table alters.
- **Deliverables**: New module `local/Tonle/Report/gpsmasterlist.py`, OpenPyXL exporter, seed script `seed_gps_master_list_report.sql`.

#### Report 4: GPS - Unplug Report (Daily)
- **Can it be created?** **CONFIRMED (YES)**.
- **Business Purpose**: Daily operational and risk alert report for GPS-equipped assets experiencing hardware disconnection, loss of satellite signal, or prolonged offline status, merged with live repayment schedule delinquency data.
- **Target Layout**: Sheet ` GPS_Daily Report` (37 columns, daily monitoring, risk ratings, recovery officers, and collection notes).
- **Database Tables Verified**: `MKT_LOAN_CONTRACT`, `MKT_CUSTOMER`, `MKT_REP_SCHEDULE`, `MKT_GPS_TRACKER`, `MKT_OFFICER`, `MKT_CATEGORY`, `MKT_COLLATERAL_DE`.
- **Schema & Data Readiness**: Financial fields and delinquency metrics are calculated dynamically from `MKT_REP_SCHEDULE`. To support daily operational case workflow, `MKT_GPS_TRACKER` requires 10 columns (`TonleStatus`, `LastServerDate`, `UnplugDays`, `Risk`, `ReInstallationCheck`, `InProgress`, `ReInstallationDate`, `Other`, `CollectorInCharge`, `PlateNumber`, `IMEI`). The complete DDL and ORM definitions are prepared.
- **Deliverables**: DDL execution in `tonle1`, ORM update in `local/Tonle/GPSTracker/models.py`, new module `local/Tonle/Report/gpsunplug.py`, OpenPyXL exporter, seed script `seed_gps_unplug_report.sql`.

#### Report 5: Insurance - Master List Control Insurance All Loans Report
- **Can it be created?** **CONFIRMED (YES)**.
- **Business Purpose**: Multi-year collateral insurance governance and renewal tracking across active and closed portfolios, plus an automated executive cross-tabulation matrix of insured vs. uninsured coverage by asset type.
- **Target Layout**: 2 Worksheets — Sheet 1: `Master list` (19 columns) and Sheet 2: `Summary` (8-column aggregation matrix with `=COUNTIF` / `=SUM` formulas).
- **Database Tables Verified**: `MKT_LOAN_CONTRACT`, `MKT_CLOSED_LOAN`, `MKT_CUSTOMER`, `MKT_INSURANCE`, `MKT_INSURANCE_COMPANY`, `MKT_PAST_DUE`, `MKT_PD_DATE`, `MKT_PRODUCT_CATALOG`.
- **Schema & Data Readiness**: 100% computable from existing contract and insurance tables. Policy renewal periods 1 and 2 map directly to `MKT_INSURANCE` (`InsurePeriod = 1` vs `2`).
- **Deliverables**: New module `local/Tonle/Report/insurancemastercontrol.py` with multi-sheet OpenPyXL builder, seed script `seed_insurance_master_control_report.sql`.

#### Report 6: Loans Closed - Master List Control All Loans Closed Report
- **Can it be created?** **CONFIRMED (YES)**.
- **Business Purpose**: Centralized master control for closed, settled (`TMN`), matured (`MRT`), and written-off (`WOF`) contracts, tracking baseline opening terms, initial vs. amended maturity dates, final payoff settlement amounts, physical document custody (`In TLF` vs `Not in TLF`), and document withdrawal dates.
- **Target Layout**: Sheet `Loans Closed` (15 columns, Row 1 Title "Tonel Finance Plc.", Row 2 Subtitle, Row 3 Header with Cyan `#00B0F0`, Peach `#F3915B`, Magenta `#F71DE7`, and Yellow `#FFFF00` fills).
- **Database Tables Verified**: `MKT_CLOSED_LOAN`, `MKT_CUSTOMER`, `MKT_LOAN_CONTRACT_HIST`, `MKT_LOAN_AMENDMENT`, `MKT_COLLATERAL_DE`, `MKT_WRITE_OFF_DE`, `MKT_COLLECTION`.
- **Schema & Data Readiness**: Baseline maturity `Date Maturity (1)` is extracted from `MKT_LOAN_CONTRACT_HIST` (`@0`). Payoff amounts are resolved from `MKT_LOAN_AMENDMENT` / `MKT_COLLECTION`. Custody status is derived from `MKT_COLLATERAL_DE.WithdrawalDate`.
- **Deliverables**: New module `local/Tonle/Report/loansclosedcontrol.py`, OpenPyXL exporter with multicolor headers, seed script `seed_loans_closed_report.sql`.

#### Report 7: CBC Enquiry Usage Report
- **Can it be created?** **CONFIRMED (YES)**.
- **Business Purpose**: Comprehensive audit, reconciliation, and sales performance tracking of Credit Bureau Cambodia (CBC) enquiries across 12 monthly cycles and weekly breakdowns by Sales Officer.
- **Target Layout**: 7 Worksheets — Sheet 1: `2026` (18-column detail transaction listing), Sheet 2: `Summary` (38-column 12-month annual matrix by Sales Officer), Sheets 3–7: `Weekly Report_January` to `Weekly Report_May` (weekly date-range breakdown matrices with `=SUBTOTAL(9, ...)` formulas).
- **Database Tables Verified**: `MKT_CBC`, `MKT_CBC_DE`, `MKT_LOAN_APPLICATION`, `MKT_CUSTOMER`, `MKT_OFFICER`, `MKT_USER`, `MKT_LOAN_PRODUCT`.
- **Schema & Data Readiness**: **0 schema changes required!** All 18 detail fields and dynamic monthly/weekly matrices are derived from existing tables. Officer names from the Excel file (e.g. *Chhan Rithy*, *Wet Sochea*, *Meas Neng*) exactly match `MKT_OFFICER` records in `tonle1`.
- **Deliverables**: New module `local/Tonle/Report/cbcenquiryusage.py` with 7-sheet OpenPyXL builder, seed script `seed_cbc_enquiry_usage_report.sql`.

#### Report 8: Loan Disbursement Report
- **Can it be created?** **CONFIRMED (YES)**.
- **Business Purpose**: Comprehensive 51-parameter loan origination, pricing breakdown, dealer commission, and logistics tracking report for all disbursed contracts.
- **Target Layout**: Sheet `Report` (51 columns, Row 1 Title "Tonle Finance", Row 2 "Loan Disbursement as of DD/MMM/YYYY", Row 4 Header columns A through AY).
- **Database Tables Verified**: `MKT_LOAN_CONTRACT`, `MKT_LOAN_APPLICATION`, `MKT_CUSTOMER`, `MKT_OFFICER`, `MKT_ASSET_DELIVERY`, `MKT_GPS_TRACKER`, `MKT_GUARANTOR`, `MKT_LOAN_CO_BORROWER`, `MKT_VENDOR`, `MKT_VENDOR_CONTACT_PERSON`, `MKT_VENDOR_BANK_ACCOUNT`, `MKT_SECTOR`, `MKT_PROVINCE`, `MKT_COLLATERAL_DE`, `MKT_LOAN_CHARGE`, `MKT_INSURANCE`.
- **Schema & Data Readiness**: **0 schema changes required!** All 51 columns are populated through standard SQL `JOIN` queries across 19 existing tables with Python calculations for `REF. Nº` (`YYYY/ProductType/LoanID/OfficerID`), Down Payment %, and Finance %.
- **Deliverables**: New module `local/Tonle/Report/loandisbursement.py`, OpenPyXL exporter with exact header titles, seed script `seed_loan_disbursement_report.sql`.

## User Review Required

> [!IMPORTANT]
> **Implementation Rollout Strategy**:
> To ensure quality and avoid database lockups or regressions in the CBS, we propose delivering the 8 reports in **4 distinct execution phases**:
> 1. **Phase 1 (Quick Wins - Existing Backend Modules)**: 
>    - **Report 1**: Asset Ownership, Registration Card & Mignette Control Report
>    - **Report 2**: Asset Ownership - Tax Paper Control Report
> 2. **Phase 2 (Zero-Schema Modification Reports)**:
>    - **Report 7**: CBC Enquiry Usage Report (7 worksheets, subtotal formulas, 0 DDL alters)
>    - **Report 8**: Loan Disbursement Report (51 columns across 19 tables, 0 DDL alters)
> 3. **Phase 3 (GPS Risk Management Reports)**:
>    - **Report 3**: GPS Master List Control All Loans (18 columns, active/closed loan unions)
>    - **Report 4**: GPS Unplug Daily Report (37 columns, requires `MKT_GPS_TRACKER` schema update)
> 4. **Phase 4 (Insurance & Portfolio Closure Reports)**:
>    - **Report 5**: Insurance Master List Control (Multi-sheet: `Master list` + `Summary` matrix)
>    - **Report 6**: Loans Closed Master List Control (15 columns, dual maturity, custody audit)

> [!WARNING]
> **Database Alteration for Report 4 (`MKT_GPS_TRACKER`)**:
> Report 4 (GPS Unplug Daily) requires adding 10 operational tracking fields to `MKT_GPS_TRACKER`, `MKT_GPS_TRACKER_INAU`, and `MKT_GPS_TRACKER_HIST` (`TonleStatus`, `LastServerDate`, `UnplugDays`, `Risk`, `ReInstallationCheck`, `InProgress`, `ReInstallationDate`, `Other`, `CollectorInCharge`, `PlateNumber`, `IMEI`).
> These alters use `ADD COLUMN IF NOT EXISTS` with safe default values so existing functionality and tests will not break.
