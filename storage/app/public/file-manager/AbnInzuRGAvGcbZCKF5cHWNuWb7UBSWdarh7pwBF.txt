# Implementation Plan & System Analysis: Tax Paper Control Report

This document presents the complete architectural review, data source analysis, gap analysis, and implementation plan for building the **Tax Paper Control Report** based on the reference Excel file:  
`2_Report Asset Ownership_  Tax Paper Control Report.xlsx`.

---

## Summary

### Overview
- **Report Name:** Asset Ownership - Tax Paper Control Report (`2_Report Asset Ownership_  Tax Paper Control Report.xlsx`).
- **Main Business Purpose:** To systematically monitor, control, and audit the physical custody and lifecycle status of heavy machinery, tractors, and agricultural/construction equipment secured by official import Tax Paper documents (វិក្កយបត្រពន្ធ / លិខិតបង់ពន្ធនាំចូល). The report tracks physical document custody (`In TLF` vs `Not in TLF`), document release/withdrawal dates (`Withdraw Date`), document filing reference codes (`Code Filling` / `Code`), asset technical specifications (Make/Model description, VIN chassis frame number, engine serial number, and asset classification), and comprehensive operational status trails across active lease contracts, paid-off loans, vendor buybacks, and written-off portfolios (`Actived Loan`, `Paid off`, `AED buy back tractor`, `Write Off`).

### Data Sources
The report consolidates data across **9 source tables** in the Tonle Core Banking System (`tonle1` database):
1. **`MKT_LOAN_CONTRACT`**: Primary active loan contract table supplying contract IDs, customer IDs, officer IDs, branch codes, loan status (`LoanStatus`), asset specifications (brand, model, series, frame/VIN number, engine number), delivery/disbursement dates, and document filing/custody fields.
2. **`MKT_CUSTOMER`**: Customer master table supplying borrower identity details (full English customer name: `LastNameEn` + `FirstNameEn`).
3. **`MKT_OFFICER`**: Loan and sales officer table supplying lending officer names (`LastName` + `FirstName`).
4. **`MKT_COLLATERAL_DE`**: Collateral detail table providing collateral document type (`Tax Paper`), custody records (`WithdrawalDate`, `WithdrawalBy`, `ReceivedBy`), and collateral filing numbers (`CollateralNumber`).
5. **`MKT_LOAN_COLLATERAL`**: Collateral bridge table linking loan contracts (`MKT_LOAN_CONTRACT`) to their corresponding collateral records (`MKT_COLLATERAL_DE`).
6. **`MKT_ASSET_DELIVERY`**: Leased asset delivery table supplying physical asset delivery dates, equipment descriptions, and delivery handover details.
7. **`MKT_CLOSED_LOAN`**: Historical closed/paid-off loan contracts table used to include historical/matured loans with tax paper custody trails (`Paid off`).
8. **`MKT_WRITE_OFF_DE`**: Written-off loan contracts detail table used to track written-off assets (`Status Trail = 'Write Off'`) and write-off notes (`Remark`).
9. **`MKT_FORECLOSED_PROPERTY`**: Foreclosed and repossessed property table supplying records for repossessed equipment and vendor buybacks (`AED buy back tractor`).

### Schema Updates
To support the operational data capture requirements of this report, **2 core tables** require schema extensions (along with their corresponding `_INAU` in-authorization and `_HIST` history audit twin tables, totaling 6 physical database tables):

1. **`MKT_LOAN_CONTRACT`** (including `MKT_LOAN_CONTRACT_INAU` and `MKT_LOAN_CONTRACT_HIST`):
   - `CodeFiling` (`VARCHAR(35)` / `db.String(35)`): Physical archive box / filing sequence number (e.g., `5`, `11`, `1084`).
   - `CollateralKeep` (`VARCHAR(50)` / `db.String(50)`): Physical document custody status / location (*In TLF*, *Not in TLF*).
   - `WithdrawDate` (`VARCHAR(10)` / `db.String(10)`): Date tax paper document was withdrawn or released to the customer (`YYYY-MM-DD`).
   - `AssetType` (`VARCHAR(50)` / `db.String(50)`): Asset classification category (*Tractor*, *Heavy Equipment*, *Vehicle*).
   - `AuditUpdate` (`VARCHAR(255)` / `db.String(255)`): Audit / operational update note for tax paper tracking.

2. **`MKT_FORECLOSED_PROPERTY`** (including `MKT_FORECLOSED_PROPERTY_INAU` and `MKT_FORECLOSED_PROPERTY_HIST`):
   - `RepoStatus` (`VARCHAR(50)` / `db.String(50)`): Asset disposition status, identifying dealer buy-backs (*AED buy back tractor*) and repossession disposition.
   - `FileNumber` (`VARCHAR(35)` / `db.String(35)`): Archive filing reference number for foreclosed/repossessed equipment.

## Phase 1: Review the Existing Core System

### Current System Status
* **The Tax Paper Control Report does not currently exist** as a dedicated report module in the CBS core system.
* What currently exists in `local/Tonle/Report/assetownership.py` is the implementation for **Report 1** (*“1_Report Asset Ownership_ Registration Card & Mignette Control Report.xlsx”*), which has a 26-column layout across 5 sheets (`Summary`, `Current Customer List`, `Repo`, `Resold`, `Car registration Name`) focused on vehicle registration cards, plates, and vignette inspections.
* The target report (**Report 2: Tax Paper Control Report**) is a dedicated 17-column report focused on machinery/tractors/equipment secured by **Tax Paper** (វិក្កយបត្រពន្ធ / លិខិតបង់ពន្ធនាំចូល) and tracks document custody (`In TLF` vs `Not in TLF`), withdrawal dates, and operational status trails (`Actived Loan`, `Paid off`, `AED buy back tractor`, `Write Off`).

### Comparison with Current Implementation
1. **Fields that exist and can be reused (11 fields):**
   - `No` (Sequence row number)
   - `AccountId` (Loan Contract ID / Account ID)
   - `AccountName` (Borrower Customer Full Name)
   - `Date Delivery` (Asset delivery / disbursement date)
   - `Description` (Asset make, model, and series description)
   - `Vin Number` (Frame/Chassis number)
   - `Engine Number` (Engine serial number)
   - `Asset Type` (Asset classification: Tractor, Heavy Equipment, Vehicle, etc.)
   - `Lending officer` (Loan officer name)
   - `Collateral Keep` (Custody status: In TLF / Not in TLF)
   - `Withdraw Date` (Date document was withdrawn/released)

2. **Fields that are missing from the current report / need implementation (4 fields):**
   - `Status Trail` (Detailed lifecycle status: `Actived Loan`, `Paid off`, `AED buy back tractor`, `Write Off`)
   - `Remark` (Additional remarks, e.g. `Write Off`)
   - `Update` (Audit / note update field)
   - `Code` (Filing sequence code / legacy ID duplicate)

3. **Fields that need modified data mapping / new business logic (2 fields):**
   - `Collateral type`: Fixed to `'Tax Paper'` (filtered/mapped for Tax Paper collaterals rather than registration cards).
   - `Code Filling`: Filing reference or numeric index extracted from loan contract / collateral code.

4. **Fields from Report 1 that are excluded in Report 2 (10 fields):**
   - `Palte Number`, `Color`, `Eng.`, `No. Of Sheats`, `Year Model`, `Issue Date`, `Car Registration NAME`, `Inspection Date`, `Expired date`, `Renew start`, `Renew end`, `Comments if Other`, `File`.

5. **Fields requiring new calculations / business logic:**
   - **Status Trail calculation:** Evaluating loan contract status (`MKT_LOAN_CONTRACT.LoanStatus`, `MKT_CLOSED_LOAN.LoanStatus`), repo/foreclosure status (`MKT_FORECLOSED_PROPERTY`, `RepoStatus`), write-off records (`MKT_WRITE_OFF_DE`), and document withdrawal status (`MKT_COLLATERAL_DE.WithdrawalDate`) to output `'Actived Loan'`, `'Paid off'`, `'AED buy back tractor'`, or `'Write Off'`.
   - **Collateral Keep calculation:** Determining `'In TLF'` when `WithdrawalDate` is empty/null, and `'Not in TLF'` when `WithdrawalDate` is set.
   - **Contract scope:** Must query both active loan contracts (`MKT_LOAN_CONTRACT`) and closed loan contracts (`MKT_CLOSED_LOAN` / `MKT_WRITE_OFF_DE`) so that historical/withdrawn tax papers (`Paid off`, `Write Off`, `AED buy back`) remain tracked in the control report as reflected in the Excel reference.

6. **Summary of field changes:**
   - Total fields in Report 2: **17 columns**.
   - Fields to add/modify compared to active report: **6 fields** (`Status Trail`, `Remark`, `Update`, `Code`, `Collateral type`, `Code Filling`).
   - Fields to remove compared to Report 1: **10 fields**.

7. **Capability of existing report engine:**
   - The Morakot `CUSTOM_REPORT` engine, `FRM_CUSTOM_REPORT_SEARCH`, and `openpyxl` exporter fully support this layout, filtering, search, pagination, and multi-format Excel generation.

### Inferred Business Rules
1. **Collateral Keep Rule:**
   $$\text{Collateral Keep} = \begin{cases} \text{'In TLF'} & \text{if } \text{Withdraw Date is null or empty} \\ \text{'Not in TLF'} & \text{if } \text{Withdraw Date is present} \end{cases}$$
2. **Status Trail Rule:**
   - If loan is active (`LoanStatus IN ('SMT', 'DIS', 'ACT')`) and not repoed/written-off: `Status Trail = 'Actived Loan'`
   - If loan is closed/matured (`MKT_CLOSED_LOAN` or `LoanStatus = 'CLS'/'MRT'`): `Status Trail = 'Paid off'`
   - If asset was repossessed or bought back by dealer (AED/vendor buyback or `RepoStatus` populated): `Status Trail = 'AED buy back tractor'`
   - If loan was written off (`MKT_WRITE_OFF_DE` or `LoanStatus = 'WOF'`): `Status Trail = 'Write Off'`
3. **Filtering & Parameters:**
   - **Branch:** Filter by branch code or 'ALL'.
   - **OfficerID:** Filter by loan officer.
   - **DateFrom / DateTo:** Filter by delivery/disbursement date range.
   - **StatusTrail / LoanStatus:** Optional dropdown filter (`All`, `Active Loan`, `Paid Off`, `Buy Back / Repo`, `Write Off`).
   - **CollateralKeep:** Optional filter (`All`, `In TLF`, `Not in TLF`).

## Phase 4: Module Analysis

### Module Placement & Architecture Recommendation
1. **Module Location:** `local/Tonle/Report/taxpapercontrol.py` (or `local/Tonle/Report/assetownership_taxpaper.py`).
2. **Why this module location is appropriate:**
   - Follows Tonle CBS custom reporting conventions (matches `assetownership.py`, `writeoffreport.py`, `creditreview.py`).
   - Keeps Report 1 (`Asset Ownership, Registration Card & Mignette Control Report`) and Report 2 (`Asset Ownership - Tax Paper Control Report`) modular, clean, and individually maintainable without risk of breaking Report 1.
3. **Route Endpoints:**
   - Web View: `/Morakot/Report/TaxPaperControl`
   - Excel Export: `/Morakot/Report/TaxPaperControl/Excel` (and `/Morakot/Report/TaxPaperControlExport`)
4. **URL & Menu Registration:**
   - Register in `local/Tonle/urlregister.py`.
   - Provide SQL seed in `local/Tonle/Report/seed_tax_paper_report.sql` to register form `TXPRPT` in `MKT_FORM`.
5. **Dependencies:**
   - `app.tools.mktcustomreport.CUSTOM_REPORT`
   - `openpyxl` for high-fidelity Excel generation.
   - `MKT_LOAN_CONTRACT`, `MKT_CLOSED_LOAN`, `MKT_COLLATERAL_DE`, `MKT_CUSTOMER`, `MKT_OFFICER`, `MKT_WRITE_OFF_DE`, `MKT_FORECLOSED_PROPERTY`.
